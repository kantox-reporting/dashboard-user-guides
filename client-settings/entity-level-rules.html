Entity Level Calculations

Learn how Status, DH Type, and Dynamic Hedging are consolidated on Entity Group Level from the Account Level .

Understanding Views

In Entity View, Status, DH Type and Dynamic Hedging describe the client (the entity group) rather than the individual account. For DH Type specifically, the entity doesn't collapse to a single winning label, it carries every live type running anywhere in the group. Here's how each one is derived, and where the two views can legitimately differ.

1

Workflow Status Hierarchy

When multiple accounts belong to an entity group, the group inherits the highest-priority workflow status. This best status then propagates downward to every single account in that entity group.

Priority Order (Highest First)
Approved Preapproved Awaiting Activation Fast Due Diligence Due Diligence Suspended Expired
Practical Consolidation Example
Account 1: Approved Account 2: Due Diligence Account 3: Suspended
All 3 accounts report: Approved

Rationale: If any part of a client has reached approved, the client relationship is an approved one. Describing the client by a lower status would understate the relationship.

2

DH Type Consolidations (K1, K2, K2B)

DH Type tracks which dynamic hedging programs are running. In Entity view, the group carries every program type that any of its live accounts run, not a single dominant winner. There is no revenue-share tiebreak: K1, K2 and K2B can all apply to the same group at once.

Scenario 1

Every Live Type Counts

If any account in the group runs K1, the group carries K1. If any account runs K2, the group also carries K2. A group can hold both at once - there's no single "winning" type.

K1 K2 No Type
Group: K1, K2
Scenario 2

Suspended Accounts Are Ignored

An account with Account Level Status = Suspended never contributes its type to the group, even if it's the only account with a type set.

K1 (active) K2 (suspended)
Group: K1 only
Scenario 3

Blank Never Overrides

An untyped account is simply left out of the calculation. It never blanks out a type that a sister account already established.

K1 No Type
Group: K1
3

Dynamic Hedging Indicator (Yes / No)

This indicator highlights if any active dynamic hedging occurs across the entity group. If at least one sister account has a defined DH Type, then the entire client group shows Yes across all accounts.

Indicator Status for an Unhedged Account
Account View
No This specific account has no hedging.
Entity View
Yes A sister account hedges. The client relationship hedges.

Important Edge-Case: If the group is Mixed and a particular account has no assigned program type, it can safely display Dynamic Hedging = Yes alongside an empty DH Type. The client demonstrably hedges, only the attribution of a specific program to this specific account is unknown.
